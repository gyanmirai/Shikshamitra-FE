# Validate School Identity

TL;DR: run focused form/permission tests and typecheck before browser acceptance. [Backend testing](../../../Shikshamitra-BE/docs/modules/institute-setup/testing.md) covers inheritance, storage, documents and authorization.

| Check | Command |
| --- | --- |
| Form/editor/permission boundaries | `npx vitest run src/screens/setting/school-identity/identity-form.test.ts src/screens/setting/school-identity/hooks/use-identity-editor.test.tsx src/screens/security/role/school-identity-permissions.test.ts` |
| Types | `npm run ts` |
| New feature lint | `npx eslint src/screens/setting/school-identity src/redux/InstituteSetup/schoolIdentityApi.ts --max-warnings 0` |
| Documentation | `node scripts/docs/validate-docs.mjs --module institute-setup` |
| Synthetic production-screen fixture | `node node_modules/vite/bin/vite.js --config e2e/fixtures/school-identity/vite.config.mjs` |
| Automated fixture workflows and responsive states | `node e2e/school-identity/check.mjs` |

Final browser acceptance must use the Codex in-app browser after automated checks. Cover defaults and partial overrides, parent selection, loading/error/retry, upload rejection, keyboard file selection, preview/download, unsaved cancellation, signature restrictions, copy confirmation, reset, and history. Check a narrow screen, both supported themes and focus visibility. Clearly label any test fixture and distinguish it from live API acceptance.

Store screenshots, generated PDFs and fixture state under ignored `.artifacts/`; never commit credentials, authentication state, or test outputs. Deployment and database migration are separate release actions, not evidence that browser acceptance has occurred.

The fixture imports the production screen and shared components, with synthetic permissions and mock API responses. It does not authenticate or write to a school. Copy the synthetic `school-identity-preview.pdf` produced by the backend PostgreSQL test into `.artifacts/school-identity/preview.pdf` before testing PDF preview/download. The fixture serves those real generated bytes; draft content and authorization require the backend tests. Missing PDF fixtures produce a visible preview error rather than a fake document.

## Academic Setup regressions

| Check | Command |
| --- | --- |
| Stage-scoped duplicate names, legacy/new API errors, onboarding contracts | `node --require ./src/test/patch-vite-windows-net-use.cjs ./node_modules/vitest/vitest.mjs run src/components/academic-setup/standard-form-model.test.ts src/components/academic-setup/onboarding-standard-form.test.tsx src/components/academic-setup/onboarding-division-model.test.ts src/utils/academic-setup-error.test.ts --pool=threads` |
| Fixture with production forms and real backend endpoints | `node node_modules/vite/bin/vite.js --config e2e/fixtures/academic-setup/vite.config.mjs` |
| Automated form/API, retry, room preservation and responsive checks | `node e2e/fixtures/academic-setup/check.mjs` |

Start the Academic Setup bridge described in the [backend testing guide](../../../Shikshamitra-BE/docs/modules/institute-setup/testing.md) first. The fixture listens at `http://127.0.0.1:4322`, uses production `ClassForm`, `DivisionForm`, shared dialogs, toast parsing and RTK Query, and labels its authentication and outer workspace as synthetic. It writes only to disposable local SQLite. A fresh bridge provides Class 1 and Class 3; restart it before rerunning the complete script.

The final Codex in-app browser smoke verifies inline duplicates, successful corrected submission, division editing/reopening, optional room selection in regular management, room-free initial setup and keyboard/responsive behavior. Automated room options are synthetic; division writes use the real disposable ABP backend. Evidence is ignored under `.artifacts/academic-setup/`. These checks do not establish QA/Staging deployment. The broader existing `api-problem-details.test.ts` currently has an unrelated admission-form approval message failure; keep it distinct from these focused checks.

## Shift tenant isolation

| Check | Command |
| --- | --- |
| Identity transition and cached bearer token | `node --require ./src/test/patch-vite-windows-net-use.cjs ./node_modules/vitest/vitest.mjs run src/redux/auth/load-session.test.tsx src/redux/session-cache.test.ts --pool=threads` |
| Production grid and standard form | `node node_modules/vite/bin/vite.js --config e2e/fixtures/shift-isolation/vite.config.mjs` |
| Automated isolation, forged foreign CRUD/reference and own edit | `node e2e/fixtures/shift-isolation/check.mjs` |

Start the backend bridge using the command in the [backend testing guide](../../../Shikshamitra-BE/docs/modules/institute-setup/testing.md) before the Vite fixture. The fixture at `http://127.0.0.1:4321` uses the production grid, ClassForm, LoadSession, session cache and RTK Query. Shift and standard requests go to the real ABP HTTP pipeline in the bridge; authentication, permissions and school context are synthetic. It never writes to QA/Staging.

The automated run expects a freshly started bridge: DDVS has four shifts, Swaminarayan is empty, and a host-only legacy shift exists. It creates and edits one synthetic Swaminarayan shift. Restart the bridge before rerunning the complete script. Save evidence to ignored `.artifacts/shift-isolation/`. Final Codex in-app browser acceptance verifies both grids, the dropdown and an owned edit after automated checks. Stop the two test servers when finished.

The existing shift form emits React warnings about nested block elements inside a paragraph. This is an unrelated baseline markup issue; the isolation checks distinguish these warnings from uncaught runtime exceptions.
