# HR column capabilities

This is the per-column follow-up to [route and table ownership](hr-table-coverage.md), audited from FE main f4613b468 and refreshed onto f2708973, with BE main 99dd6973. The earlier adapter inventory did not establish column-level coverage. The user screenshot was independently inspected by the cloud consumer and identified Staff Directory; it showed no visible sort affordances. Current shared headers now show a neutral sort icon before selection. Screenshot identity does not establish the deployed commit.

Run `node scripts/hr/check-column-capabilities.mjs --json` for the route/table/column matrix, declared choices, authorized source mapping and computed accessors. Run `node --test scripts/hr/column-capabilities.test.mjs` for coverage regressions. The AST reader never executes screen code. It includes all imported route branches and permission-conditional column unions; import closure does not assert every table renders on every route.

There are 80 definitions/call sites, 464 explicit column occurrences, 14 schema-parametric entries and two editable grids. Counts include wrapper definitions and their consumers. Every formerly unresolved site is listed here; dynamic fields are governed by their explicit schema rule. Runtime evidence is separate from static coverage.

## Reading the matrix

All listed data columns sort ascending/descending and have the shown filter. Global sources use the authorized complete population before pagination/count/export. Local collections sort/filter their complete returned collection. Choice controls retain their actual labels and codes, including zero/false. Actions/selection/navigation columns marked **control** do not sort/filter/export. Table exports use visible ordered data columns; draft/selection surfaces retain their explicit export restrictions.

## Semantics and deliberate differences

- Staff Directory Name and I-card Staff predicates match the displayed employee identifier as well as the name; ordering remains by name. Raw editing envelopes and selected-ID caches remain intact. Group, gender and lifecycle filters use named choices; dates use date predicates and phone/code strings retain leading zeroes.
- Register Exceptions include only positive visible categories; a locked-only row does not match Absent. Editability omits a zero locked count. Nested daily Lock has named choices; hours compare decimal durations. Open adjustment/bulk dialogs and pending saves guard criteria, search and pagination.
- Operational metadata preserves declared categorical controls and operator restrictions. Backend enum labels and native zero/false codes represent one field, with derived lifecycle labels kept distinct. ESI top-level Coverage/Readiness criteria retain their owning-reader semantics; they are not reused as generic cell-equality values.
- Audit weekday arrays, objects, references and dates use the same readable, redacted text for predicates, sorting and export. An explicit search accessor does not fall back to a hidden raw reference.
- Salary component cards use the embedded shared table. Numeric criteria compare amounts; the card total remains the complete payroll component total. Filtering does not recalculate an official payroll amount.
- The report designer explicitly labels its first-50-row preview sample; local controls refine that sample and its export applies criteria to the complete captured output. Open a captured result for full-population server paging. Configured report fields use server-selected metadata; boolean/options are choices, money/numbers numeric, dates/timestamps date controls.
- The chronological payroll-basis editing grid and holiday-inclusion editing grid retain their drafting controls. Their exact columns and behavior-specific exceptions are enumerated above.
- I-card staff selection and editable salary component forms do not gain unrestricted table export; their existing selected-card/document and editing workflows remain authoritative. No permission or tenant-scope grants are added.

## Validation and remaining limits

The final run and exact commits are recorded in [HR testing](../testing.md). Synthetic browser cases use actual shared headers, directory metadata, I-card columns, Register guard, query/export hooks and salary tables with local transports. They do not establish authenticated tenant acceptance or deployed commit identity. The original screenshot could not be materialized on this Windows executor because the supported Library helper requires unavailable os.setxattr; its pixels were inspected independently by the cloud consumer.
